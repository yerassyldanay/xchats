# Definition of Done — per phase

Acceptance criteria for each build phase from `0-overview.md`. A phase is **done** only when its
checklist passes — verified by the isolated harness in `6-isolated-testing.md` (no real WhatsApp).
Each phase builds on the previous.

## Phase 1 — Foundation (runnable skeleton)

Done when:
- The monorepo exists: `backend/` (Go module) + `frontend/` (Vue/Vite) + `deploy/` (compose +
  optional `postgres.compose.yaml` / `redis.compose.yaml` + Makefile) + single `.env(.example)` /
  `config.yaml(.example)`.
- `make up` starts the stack against the **reused** Postgres by default; `make up-local` runs it
  against the optional local datastore composes — switching is **env-only** (no code change).
- Backend boots, connects to Postgres, **applies migrations** (all `xchats.*` tables from
  `9-database-schema.md`), and serves `GET /healthz` (200) and `GET /readyz`.
- The **Evolution bootstrap** runs idempotently: ensures the instance + sets the webhook to
  `/evolution/api/v1/webhook/{account}` with the shared token; re-running is safe.
- Seed: `config.yaml` users + default org are **upserted** on startup; login works
  (`POST /xchats/api/v1/auth/login` → session; `GET /me` returns the user+org).
- Frontend serves on its own port and reaches the backend via `API_BASE_URL`.

Verify: `make up` healthy + tables present; `make up-local` works with no code change; bootstrap
logs show `webhook/set` succeeded; login round-trips.

## Phase 2 — Backend transport (the core loop)

Done when (all via the **fake Evolution + `captures/` fixtures**, `make test-e2e`):
- Webhook edge: stores raw to `xchats.evolution_events`, returns 200 fast, enqueues; a **replayed event is a
  no-op** (idempotent on `(account, evo_event_kind, external_event_id)`).
- Normalizer parity: output matches `scripts/evolution_client.py` for the same fixtures
  (text + media, `@lid`↔phone via `remoteJidAlt`, status 0-5).
- Inbound `messages.upsert` → upserts `xchats.contacts` (+ identities), `xchats.conversations` (keyed on phone),
  `xchats.messages`; **no duplicates** on replay.
- Media: an `imageMessage` enqueues a download that fetches via `getBase64FromMediaMessage` (fake)
  and writes `xchats.message_media` `dl_state: pending → ready` with a `store_url`.
- Outbound: `POST /xchats/api/v1/conversations/{id}/messages` → `xchats.jobs` `outbound_send` → fake
  Evolution receives a send **to the phone, not the `@lid`**; `evo_message_id` stored.
- Status: replayed `messages.update` moves `delivery_state` `sent → delivered → read`
  **monotonically** (a late event never downgrades), correlated by `evo_message_id == keyId`.
- Responses follow the `{payload, errcode}` envelope + status mapping in `7-api-contracts.md`.

Verify: `make test-e2e` green; the full inbound→store and send→status loops assert against fixtures.

## Phase 3 — UI (inbox + connect)

Done when:
- Login; **WhatsApp accounts** page lists all instances with status + assign/unassign; **Add
  account** → name → QR → (on connect) assigned.
- Inbox: conversation list (filters), chat view with inbound/outbound bubbles, media, and
  **delivery/read ticks**; send text + media.
- Live updates over **SSE** (`message.*`, `conversation.*`, `whatsapp_account.status_changed`,
  `sync.progress`).
- The UI talks **only** to `/xchats/api/v1` (+ realtime); same flows pass against the fake backend.

Verify: component tests (Vitest) pass; an e2e drives login → (faked) connect → see a fixture
message live → send → tick updates. (Connecting a **real** number is a manual smoke outside isolation.)

## Phase 4 — AI assistant

Done when (per `8.6-port-checklist.md`):
- The brain is ported; `go test ./internal/assistant/...` passes after the module-path rewrite.
- Config (persona/topics/assets/prices) is stored in Postgres (`xchats.ai_*`); the **admin UI** edits +
  publish/rollback works; **Playground** returns a `Draft` from a Postgres-loaded snapshot.
- On inbound, the `ai_draft` job runs `HandleMessage` → writes `xchats.ai_drafts` + emits
  `ai_draft.created`; the UI shows the suggestion; **approve → sends** via the Phase-2 pipeline
  (`sender_kind='ai'`).
- Guardrails honored: prices are tokens until injected; media only by catalog refs (max 3); reply
  in the customer's language; suggest-only unless `xchats.organizations.respond_mode` allows auto-send; no draft
  on `syncing/partial` context without the `context_state` flag.

Verify: an inbound fixture produces a valid `xchats.ai_drafts`; approve-draft round-trips to a sent
message with status updates.

## Global "ready" bar

The plan is **delivered** when Phases 1–4 are individually done **and** `make test-e2e` runs the
whole loop green in an isolated environment from one command, plus one manual real-Evolution smoke
(`localhost:9700`) confirming live connectivity.
