# KB Builder — Schema (additive DDL)

Concrete, ready-to-run Postgres DDL for the builder. Two migrations: **`0003`** realizes the snapshot
KB tables that `9-database-schema.md` *designed but deferred* (only `ai_drafts`/`ai_draft_assets` are
migrated today — see `backend/migrations/0001_init.up.sql`); **`0004`** adds the builder/changeset
tables. **Everything is additive** — new tables + nullable columns. The live runtime tables and the
brain stay byte-compatible.

Conventions follow `9-database-schema.md`: schema `xchats`, `uuid` PKs (`uuid_generate_v4()`),
`timestamptz` (UTC), enum-likes are `text`, 3NF (no repeated `organization_id` where derivable),
`jsonb` for open documents.

---

## Migration `0003` — the snapshot KB (realizes `9`'s deferred `ai_*` tables)

This is **Phase 11A** and a prerequisite for the builder *and* for the real (non-stub) brain. Mirrors
`9-database-schema.md` exactly, with **two deliberate, documented extensions** flagged `[+]`.

```sql
-- 0003_ai_snapshot_kb.up.sql
SET search_path = xchats, public;

-- A versioned config the prompt is built from. publish swaps the live one atomically; rollback
-- re-publishes a prior version.
CREATE TABLE IF NOT EXISTS xchats.ai_snapshots (
    id              uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    organization_id uuid NOT NULL REFERENCES xchats.organizations(id) ON DELETE CASCADE,
    version         int  NOT NULL,
    snapshot_state  text NOT NULL DEFAULT 'draft',   -- 'draft' | 'published' | 'archived'  [+]
    -- the four operator-editable config blocks (8-ai-assistant.md → prompt [B]/[C]):
    persona         text NOT NULL DEFAULT '',        -- block: IDENTITY
    mission         text NOT NULL DEFAULT '',        -- block: GOAL (folded into [B])
    guardrails      text NOT NULL DEFAULT '',        -- block: QUALITY standards ([C])
    support_policy  text NOT NULL DEFAULT '',        -- block: SUPPORT behavior ([C], appended)  [+]
    language_policy text NOT NULL DEFAULT '',        -- code/default-managed sub-rule of support
    published_at    timestamptz,
    created_at      timestamptz NOT NULL DEFAULT now(),
    updated_at      timestamptz NOT NULL DEFAULT now(),
    UNIQUE (organization_id, version)
);
-- exactly one live snapshot per org, and one open working draft per org:
CREATE UNIQUE INDEX IF NOT EXISTS ai_snapshots_one_published
    ON xchats.ai_snapshots(organization_id) WHERE snapshot_state = 'published';
CREATE UNIQUE INDEX IF NOT EXISTS ai_snapshots_one_draft
    ON xchats.ai_snapshots(organization_id) WHERE snapshot_state = 'draft';

CREATE TABLE IF NOT EXISTS xchats.ai_topics (
    id           uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    snapshot_id  uuid NOT NULL REFERENCES xchats.ai_snapshots(id) ON DELETE CASCADE,
    slug         text NOT NULL,
    lang         text NOT NULL DEFAULT 'ru',
    keywords     text NOT NULL DEFAULT '',
    body_md      text NOT NULL DEFAULT '',           -- price TOKENS only, never digits
    review_state text NOT NULL DEFAULT 'approved',   -- 'proposed'|'approved'|'rejected'   [+ builder]
    provenance   jsonb,                              -- {source:'chat|url|file', ref:'…'}   [+ builder]
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (snapshot_id, slug)
);

CREATE TABLE IF NOT EXISTS xchats.ai_assets (
    id           uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    snapshot_id  uuid NOT NULL REFERENCES xchats.ai_snapshots(id) ON DELETE CASCADE,
    ref          text NOT NULL,                      -- stable id the model uses in asset_refs
    asset_kind   text NOT NULL,                      -- 'image'|'video'|'document'|'audio'|'link'  [+'link']
    topic_slug   text NOT NULL DEFAULT '',           -- links the asset to its container topic
    description  text NOT NULL DEFAULT '',           -- the per-asset SELECTION cue ("what + when to send")
    asset_url    text NOT NULL DEFAULT '',           -- blob URL, or the external URL when kind='link'
    review_state text NOT NULL DEFAULT 'approved',   -- [+ builder]
    provenance   jsonb,                              -- [+ builder]
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (snapshot_id, ref)
);

CREATE TABLE IF NOT EXISTS xchats.ai_prices (
    id           uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    snapshot_id  uuid NOT NULL REFERENCES xchats.ai_snapshots(id) ON DELETE CASCADE,
    token        text NOT NULL,                      -- e.g. 'price.growth'
    amount_text  text NOT NULL DEFAULT '',           -- the real value, human-confirmed
    review_state text NOT NULL DEFAULT 'approved',   -- [+ builder]
    provenance   jsonb,                              -- [+ builder]
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now(),
    UNIQUE (snapshot_id, token)
);

CREATE TABLE IF NOT EXISTS xchats.ai_audit_log (
    id              uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    organization_id uuid NOT NULL REFERENCES xchats.organizations(id) ON DELETE CASCADE,
    action          text NOT NULL,                   -- 'publish'|'rollback'|'changeset.apply'|…
    actor_user_id   uuid REFERENCES xchats.users(id) ON DELETE SET NULL,
    version         int,
    note            text NOT NULL DEFAULT '',
    created_at      timestamptz NOT NULL DEFAULT now()
);
```

### The two `[+]` extensions to `9-database-schema.md` (called out, not silent)

1. **`snapshot_state` gains `'archived'`** (was `'draft'|'published'`). Publish = archive the current
   published row, mark the draft published — so `ai_snapshots_one_published` holds and **rollback** is
   just "re-publish an archived version." Additive (a text value), no migration pain. Update `9`'s enum
   note when this lands.
2. **`support_policy` column** + **`asset_kind='link'`** — the SUPPORT block (`11`, §4) and links as
   first-class assets (infographics/PDFs/videos/links are all `ai_assets`, differing only by
   `asset_kind`). `BuildSystem` appends `support_policy` to prompt block `[C]` (the one ~3-line brain
   touch).

> **`ai_drafts.trigger_message_id`** stays as in `0001`. **Seed import:** on first boot, if the org has
> no `published` snapshot, load `0002_seed.sql` (persona/topics/assets/prices) as **version 1,
> published** — the cold-start fix (`8-ai-assistant.md`). The builder later forks a `draft` from it.

## Migration `0004` — the builder & changeset tables (Phase 11B–11C)

```sql
-- 0004_kb_builder.up.sql
SET search_path = xchats, public;

-- One authoring conversation, bound to the draft snapshot it edits.
CREATE TABLE IF NOT EXISTS xchats.ai_builder_sessions (
    id           uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    snapshot_id  uuid NOT NULL REFERENCES xchats.ai_snapshots(id) ON DELETE CASCADE,  -- the DRAFT being built
    started_by   uuid REFERENCES xchats.users(id) ON DELETE SET NULL,
    state        text NOT NULL DEFAULT 'open',       -- 'open'|'published'|'abandoned'
    created_at   timestamptz NOT NULL DEFAULT now(),
    updated_at   timestamptz NOT NULL DEFAULT now()
);
CREATE UNIQUE INDEX IF NOT EXISTS ai_builder_sessions_one_open
    ON xchats.ai_builder_sessions(snapshot_id) WHERE state = 'open';

-- The chat transcript (user turns, assistant turns, tool calls/results).
CREATE TABLE IF NOT EXISTS xchats.ai_builder_messages (
    id           uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id   uuid NOT NULL REFERENCES xchats.ai_builder_sessions(id) ON DELETE CASCADE,
    role         text NOT NULL,                      -- 'user'|'assistant'|'tool'|'system'
    content      text NOT NULL DEFAULT '',           -- the visible message text
    tool_calls   jsonb,                              -- assistant tool calls this turn (audit/replay)
    tool_name    text NOT NULL DEFAULT '',           -- set when role='tool'
    refs         jsonb,                              -- {changeset_id?, request_id?, topic_slug?, asset_ref?}
    created_at   timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ai_builder_messages_session_idx
    ON xchats.ai_builder_messages(session_id, created_at);

-- An uploaded file in the builder, + its normalization state. Bytes live in the blob store.
CREATE TABLE IF NOT EXISTS xchats.ai_builder_attachments (
    id            uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id    uuid NOT NULL REFERENCES xchats.ai_builder_sessions(id) ON DELETE CASCADE,
    message_id    uuid REFERENCES xchats.ai_builder_messages(id) ON DELETE SET NULL,
    blob_id       text NOT NULL DEFAULT '',          -- key in internal/blob (empty for kind='link')
    source_kind   text NOT NULL,                     -- 'image'|'video'|'audio'|'document'|'link'|'text'
    source_url    text NOT NULL DEFAULT '',          -- the link/url, when applicable
    file_name     text NOT NULL DEFAULT '',
    mimetype      text NOT NULL DEFAULT '',
    file_size     int  NOT NULL DEFAULT 0,
    norm_state    text NOT NULL DEFAULT 'pending',   -- 'pending'|'normalized'|'needs_description'|'failed'
    extracted_text text NOT NULL DEFAULT '',         -- url/pdf/doc extraction result (empty if none)
    created_at    timestamptz NOT NULL DEFAULT now(),
    updated_at    timestamptz NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS ai_builder_attachments_session_idx
    ON xchats.ai_builder_attachments(session_id);

-- Human-in-the-loop POPUPS the agent raises (describe_media, confirm_price, …).
CREATE TABLE IF NOT EXISTS xchats.ai_builder_requests (
    id            uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    session_id    uuid NOT NULL REFERENCES xchats.ai_builder_sessions(id) ON DELETE CASCADE,
    req_type      text NOT NULL,                     -- 'describe_media'|'confirm_price'|'approve_topic'
                                                     -- |'approve_asset'|'resolve_duplicate'|'choose_topic'|'comment'
    prompt        text NOT NULL DEFAULT '',          -- what the popup asks the human
    context       jsonb,                             -- {thumbnail?, topic_slug?, detected_value?, candidates?}
    target_kind   text NOT NULL DEFAULT '',          -- 'asset'|'price'|'topic'
    target_ref    text NOT NULL DEFAULT '',          -- the draft row it resolves into
    state         text NOT NULL DEFAULT 'pending',   -- 'pending'|'resolved'|'dismissed'
    resolution    jsonb,                             -- the human's answer (text/accept/edit/merge)
    created_at    timestamptz NOT NULL DEFAULT now(),
    resolved_at   timestamptz
);
CREATE INDEX IF NOT EXISTS ai_builder_requests_open_idx
    ON xchats.ai_builder_requests(session_id) WHERE state = 'pending';

-- ── Changesets: the git-like diff unit for IMPORTANT changes (11, §5) ──────────────────────────────
CREATE TABLE IF NOT EXISTS xchats.ai_changesets (
    id            uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    snapshot_id   uuid NOT NULL REFERENCES xchats.ai_snapshots(id) ON DELETE CASCADE,  -- the DRAFT
    session_id    uuid REFERENCES xchats.ai_builder_sessions(id) ON DELETE SET NULL,
    title         text NOT NULL DEFAULT '',          -- "Add Рост tariff card + bump price"
    summary       text NOT NULL DEFAULT '',          -- one-line intent (the agent writes it)
    origin_message_id uuid REFERENCES xchats.ai_builder_messages(id) ON DELETE SET NULL,
    state         text NOT NULL DEFAULT 'proposed',  -- 'proposed'|'applied'|'discarded'
    created_at    timestamptz NOT NULL DEFAULT now(),
    applied_at    timestamptz,
    applied_by    uuid REFERENCES xchats.users(id) ON DELETE SET NULL
);
CREATE INDEX IF NOT EXISTS ai_changesets_open_idx
    ON xchats.ai_changesets(snapshot_id) WHERE state = 'proposed';

-- One typed before/after edit inside a changeset → renders as a git hunk.
CREATE TABLE IF NOT EXISTS xchats.ai_change_ops (
    id            uuid PRIMARY KEY DEFAULT uuid_generate_v4(),
    changeset_id  uuid NOT NULL REFERENCES xchats.ai_changesets(id) ON DELETE CASCADE,
    op            text NOT NULL,                      -- 'create'|'update'|'delete'
    target_kind   text NOT NULL,                      -- 'block'|'topic'|'asset'|'price'
    target_ref    text NOT NULL,                      -- block key / topic slug / asset ref / price token
    before_json   jsonb,                              -- null on create
    after_json    jsonb,                              -- null on delete
    ordinal       int  NOT NULL DEFAULT 0,
    UNIQUE (changeset_id, ordinal)
);
```

## How apply works (the transaction)

`POST …/changesets/{id}/apply` runs **one transaction**, idempotent on the changeset state:

```text
BEGIN;
  -- guard: only apply once (409 CONFLICT otherwise)
  UPDATE ai_changesets SET state='applied', applied_at=now(), applied_by=:user
    WHERE id=:id AND state='proposed';            -- 0 rows ⇒ already applied/discarded ⇒ 409
  FOR each op ORDER BY ordinal:
     block → UPDATE ai_snapshots SET <col>=after  WHERE id=:draft
     topic → INSERT/UPDATE/DELETE ai_topics       (provenance := op origin; review_state := 'approved')
     asset → INSERT/UPDATE/DELETE ai_assets
     price → INSERT/UPDATE ai_prices              (only via a resolved confirm_price)
  INSERT ai_audit_log(action='changeset.apply', version=draft.version, note=title);
COMMIT;
```

Apply only ever mutates the **draft** snapshot (`snapshot_state='draft'`). The live snapshot and the
brain are never touched until **publish** (`11.2`). Discard sets `state='discarded'` and changes
nothing else.

## Provenance shape

`provenance` (on topics/assets/prices) and a change-op's origin share one shape, so the editor and the
diff can both show "created from …":

```jsonc
{ "source": "chat" | "url" | "file" | "seed",
  "ref": "builder_message_id | https://… | attachment_id",
  "session_id": "uuid", "at": "ts" }
```

## Constraints that carry weight

```text
ai_snapshots_one_published   one live snapshot per org           (publish swaps atomically)
ai_snapshots_one_draft       one working draft per org           (the builder's single canvas)
ai_builder_sessions_one_open one open builder chat per draft     (no split-brain authoring)
ai_drafts_pending_uq (0001)  ≤3 pending suggestion options       (runtime, unchanged)
ai_change_ops UNIQUE(cs,ord) stable diff ordering
ai_changesets state guard    apply-once via conditional UPDATE   (idempotent, 409 on replay)
```

## What is NOT added (kept simple, on purpose)

- **No vector/embedding tables.** Curated-in-prompt KB (`8-ai-assistant.md` → Scaling); add `pgvector`
  only when the KB outgrows the prompt — additive, behind the same context port.
- **No per-op review_state.** Acceptance lives at the **changeset** level (apply/discard) for important
  edits and at the **row** level (`review_state`) for the low-stakes stream — not both per op.
- **No new queue table.** Slow intake (URL fetch, PDF extract) rides the existing in-memory `Queue`
  port (`9-database-schema.md` → Async queue); attachment `norm_state` is the durable status.
