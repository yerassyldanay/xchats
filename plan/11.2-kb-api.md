# KB Builder — API & realtime

The HTTP surface for the builder chat, the editor CRUD, requests (popups), changesets (diffs), and
publish. Conventions, the `{payload, errcode, message}` envelope, error codes, and HTTP statuses are in
`7-api-contracts.md`; **Response** below shows the contents of `payload` on success. All routes are
**authenticated** and mount under `/xchats/api/v1`. This **supersedes** the three deferred placeholders
in `7.1-endpoints.md` (`/assistant/config`, `/assistant/publish`, `/assistant/playground`) with the
full set.

## Error codes — reuse, plus the minimum new

Reuse `OK · VALIDATION_ERROR · UNAUTHORIZED · NOT_FOUND · CONFLICT · RATE_LIMITED · AI_UNAVAILABLE ·
EVAL_GATE_FAILED · INTERNAL` from `7-api-contracts.md`. Mappings specific to the builder:

| Situation | errcode (HTTP) |
|---|---|
| Apply/discard a changeset that's already applied/discarded | `CONFLICT` (409) |
| Resolve a request that's already resolved/dismissed | `CONFLICT` (409) |
| Publish refused — failing metric **or** unresolved requests/unconfirmed prices | `EVAL_GATE_FAILED` (409) |
| Builder agent / extractor LLM unavailable | `AI_UNAVAILABLE` (503) |
| Upload too large / bad type | `VALIDATION_ERROR` (400) / `MEDIA_UNAVAILABLE` (502) |

> **No new error codes.** `EVAL_GATE_FAILED`'s payload is **extended** to carry both the metric failures
> *and* the list of unresolved requests/unconfirmed prices (so the UI shows exactly what blocks publish).

## Builder chat — `/xchats/api/v1/assistant/builder`

### POST /assistant/builder/session   (get-or-create the working session)
- **Body:** none. Idempotent: returns the org's **open** session; if none, **forks a `draft`** snapshot
  from the current `published` one (copying blocks/topics/assets/prices) and opens a session on it.
- **Response:** `BuilderSession` (201 when created, 200 when reused).

### GET /assistant/builder/session
- **Response:** `BuilderSession` + `{ "messages_tail":[ BuilderMessage ], "open_requests":[ BuilderRequest ],
  "open_changesets":[ Changeset ] }` — everything needed to hydrate the chat on load.
- **Errors:** `NOT_FOUND` (no open session — call POST first).

### POST /assistant/builder/messages   (the operator says something / drops material)
- **Body:** `{ "text?":"Вот наши тарифы…", "link?":"https://…", "attachment_ids?":["uuid"] }` — any
  combination (a plain note, a link, and/or files already uploaded below).
- **Behavior:** persists the user turn, then enqueues an **agent run** (`ai_builder` task on the existing
  queue). The agent's reply, any tool effects (proposed rows), requests, and changesets arrive over SSE.
- **Response:** `202 { "message_id":"uuid" }`. · **Errors:** `AI_UNAVAILABLE` (503), `VALIDATION_ERROR`.

### GET /assistant/builder/messages
- **Query:** `before?`, `limit?` → `{ "items":[ BuilderMessage ], "next_before":"cursor|null" }`.

### POST /assistant/builder/attachments   (upload a file or register a link)
- **Body:** `multipart/form-data` with a `file` part, **or** JSON `{ "url":"https://…" }` for a link.
- **Behavior:** stores bytes via the existing blob store, creates `ai_builder_attachments` (`norm_state
  ='pending'`), and enqueues normalization (URL fetch / PDF extract / else → `needs_description`).
- **Response:** `201 BuilderAttachment`. Then reference its `id` in `POST …/messages` `attachment_ids`.
- **Errors:** `VALIDATION_ERROR` (bad type/size), `MEDIA_UNAVAILABLE` (502).

## Requests (popups) — `/xchats/api/v1/assistant/builder/requests`

### GET …/requests
- **Query:** `state?=pending|resolved` → `{ "items":[ BuilderRequest ] }` (default `pending`).

### POST …/requests/{id}/resolve
- **Body (by `req_type`):**
  - `describe_media` → `{ "description":"Карточка тарифа Рост — когда клиент спрашивает про Рост." , "topic_slug?":"tariffs", "asset_kind?":"image" }`
  - `confirm_price` → `{ "action":"accept|edit", "amount_text?":"28 000 ₸", "token?":"price.growth" }`
  - `approve_topic` / `approve_asset` → `{ "action":"accept|reject|edit", "patch?":{…} }`
  - `resolve_duplicate` → `{ "action":"merge|keep_both", "into?":"tariffs" }`
  - `choose_topic` → `{ "topic_slug":"tariffs" }` or `{ "create":"new_slug" }`
  - `comment` → `{ "text":"focus on retail clients" }`
  - any → `{ "action":"dismiss" }`
- **Behavior:** writes the resolution into the draft (sets the asset description, the price token, the
  `review_state`, the merge…), marks the request `resolved`, and **nudges the agent** (a follow-up run)
  so it can continue. Emits `builder.request.resolved` + the relevant `builder.draft.updated`.
- **Response:** the updated `BuilderRequest`. · **Errors:** `CONFLICT` (already resolved), `VALIDATION_ERROR`.

## Changesets (git-like diffs) — `/xchats/api/v1/assistant/builder/changesets`

### GET …/changesets
- **Query:** `state?=proposed|applied|discarded` → `{ "items":[ Changeset ] }` (default `proposed`).

### GET …/changesets/{id}
- **Response:** the full `Changeset` with every `ChangeOp` (`before`/`after` per field) — the data the
  UI renders as a diff. `needs[]` lists blocking requests (e.g. an unconfirmed price in this set).

### POST …/changesets/{id}/apply
- **Body:** none. Runs the **apply transaction** (`11.1`): mutates the draft rows in `ordinal` order,
  stamps provenance, writes `ai_audit_log`, marks the changeset `applied`. **Idempotent** (conditional
  `UPDATE … WHERE state='proposed'`).
- **Response:** the `Changeset` (`state:applied`) + `{ "draft_version":2 }`.
- **Errors:** `CONFLICT` (409, already applied/discarded), `EVAL_GATE_FAILED` (409, has unresolved
  `needs` — e.g. a price op without its `confirm_price`).

### POST …/changesets/{id}/discard
- **Body:** `{ "reason?":"…" }` → marks `discarded`, mutates nothing. **Response:** the `Changeset`.

## Editor CRUD (the precise path; same draft) — `/xchats/api/v1/assistant`

> The editor edits the **draft** directly (the human is reviewing as they type — no diff needed for
> *manual* edits). The **agent's** important edits arrive as changesets (above). Both write the same
> draft rows.

```text
GET    /assistant/config?state=draft|published     full snapshot: blocks + topics(+assets) + prices
PUT    /assistant/blocks/{key}                     {body}  edit identity|goal|quality|support (direct)
POST   /assistant/topics                           {slug,lang,keywords,body_md}
PUT    /assistant/topics/{slug}                    patch body/keywords/lang
DELETE /assistant/topics/{slug}
POST   /assistant/assets                            {ref,asset_kind,topic_slug,description,media_id|url}
PUT    /assistant/assets/{ref}                      patch description/topic_slug/kind
DELETE /assistant/assets/{ref}
POST   /assistant/prices                            {token,amount_text}
PUT    /assistant/prices/{token}                    {amount_text}
DELETE /assistant/prices/{token}
POST   /assistant/review                            {kind:'topic|asset|price', ref, action:'accept|reject'}
```

- `GET /assistant/config` **Response:** `{ "version", "state", "blocks":[ ConfigBlock ],
  "topics":[ Topic ], "prices":[ Price ], "open_requests":n, "open_changesets":n }`.
- Asset create accepts **either** a `media_id` (from `POST /media`) **or** a `url` (a `link` asset).
- All editor writes emit `builder.draft.updated` so the chat and editor stay in sync.

## Publish / rollback / versions — `/xchats/api/v1/assistant`

### POST /assistant/publish
- **Body:** none (publishes the org's current `draft`).
- **Gate (refuses unless all pass):** deterministic golden-set metrics — **price-safety = 1.0**,
  **asset-precision ≥ 0.9** (thresholds in `config.yaml`, `8.7-ai-evals.md`) — **and** zero `pending`
  requests, **and** every `{{token}}` in any topic body resolves to a price row, **and** no `proposed`
  rows left un-accepted (rejected rows are excluded).
- **On pass:** one transaction — archive the current `published`, mark the draft `published`, set
  `published_at` + bump nothing (version already assigned), write `ai_audit_log(action='publish')`, and
  **reload the brain's in-memory snapshot**. Closes the builder session (`state='published'`).
- **Response:** `{ "version":2, "published_at":"ts", "eval":{ "price_safety":1.0, "asset_precision":0.95,
  "judge_mean?":4.3 } }`.
- **Errors:** `EVAL_GATE_FAILED` (409, payload = `{ "metrics":{…}, "unresolved":[ "confirm_price:price.growth",
  "describe_media:tariffs_growth" ] }`).

### POST /assistant/rollback
- **Body:** `{ "version": 1 }` → re-publish an `archived` version (archive current, un-archive target,
  reload the brain). **Response:** `{ "version":1, "published_at":"ts" }`. · **Errors:** `NOT_FOUND`.

### GET /assistant/versions
- **Response:** `{ "items":[ { "version", "state", "published_at", "topic_count", "note" } ] }` — the
  history for rollback + audit.

### POST /assistant/playground   *(dry-run a draft; no send — from 7.1, kept)*
- **Body:** `{ "messages":[{ "role":"customer|agent","content":"…" }], "profile?":{…} }`.
- **Response:** an `AiDraft`-shaped result from the **draft** snapshot, so the operator can test the KB
  *before* publishing. See `8-ai-assistant.md`.

## Realtime — extends `GET /xchats/api/v1/realtime` (SSE)

New event types on the **existing** SSE stream (`internal/realtime` hub; `2-architecture.md`):

| event | `data` | UI effect |
|---|---|---|
| `builder.message` | `BuilderMessage` | append the agent's turn to the chat |
| `builder.attachment.updated` | `BuilderAttachment` | flip a file to "needs description" / "ready" |
| `builder.request.created` | `BuilderRequest` | pop a popup card (chat) + bump the editor review badge |
| `builder.request.resolved` | `{ id, state }` | dismiss the popup |
| `builder.changeset.created` | `Changeset` | render a diff card in the chat |
| `builder.changeset.applied` / `.discarded` | `{ id, state }` | collapse the diff card; refresh editor |
| `builder.draft.updated` | `{ kind, ref }` | refresh the changed editor row |
| `assistant.published` | `{ version }` | toast "Опубликовано v2"; brain now answers from it |

Each `data` is the entity in the shapes above. The builder reuses the one SSE channel — no new
transport.
