# KB Builder — UI surfaces

Two surfaces over **one** draft Snapshot (`11`, §1): the **builder chat** (fast, conversational) and
the **KB editor** (precise, structured). Same design language and conventions as `5-ui-pages.md`
(Russian UI, indigo `#4F46E5`, WhatsApp-green `#22C55E` for go/confirm, the three visibility tiers, the
**"every element is backed"** hard rule). These specs are image-generation-ready. This expands the
deferred `/assistant` page from `5-ui-pages.md` §5.

> **Hard rule (carried from `5-ui-pages.md`).** Nothing shows data we can't retrieve or triggers an
> action we don't expose. Each region lists **▸ Backed by:** the exact endpoint(s) from `11.2`.

- **Tier 1 (core):** the chat composer, the topic list, the four block tiles, the publish bar.
- **Tier 2 (one click):** expand a topic → its body + media gallery; open a block → its editor; open a

- **Tier 3 (drawer):** provenance ("из: сообщение #12 / источник: …"), version history, the playground.

## Pane A — Builder chat (Сборка)

The fast path. Drop material, watch rows appear, answer popups, approve diffs.

- **Transcript:** operator turns (with attachment chips) and assistant turns (short: *what it did +
  what it needs*). Assistant rows that created data show an inline **"→ tema «tariffs»"** link that
  scrolls the editor to that row.
- **Composer:** a text field + **📎 attach** (file) + **🔗 link** + send. Attaching N files uploads them
  (`POST …/attachments`) and references them in the next message. A file still normalizing shows a
  small spinner → flips to a **"опишите файл"** chip when it needs a description.
- **Inline popup cards (requests):** rendered where they occur (and mirrored in the editor's review
  queue). Each is small and single-purpose:
  - `describe_media` — a **thumbnail** + a textarea "Опишите, что показано и когда это отправлять" +
    optional topic picker → **Сохранить**.
  - `confirm_price` — "Сопоставить «25 000 ₸» → `{{price.growth}}`?" with **Принять / Изменить**.
  - `approve_topic`/`approve_asset` — **Принять · Изменить · Отклонить**.
  - `resolve_duplicate` — **Объединить / Оставить оба**.
  - `choose_topic` — a topic picker / **+ создать**.
- **Inline diff cards (changesets):** see below.
- **▸ Backed by:** `POST/GET …/builder/session`, `POST/GET …/builder/messages`,
  `POST …/builder/attachments`, `GET …/builder/requests`, `POST …/builder/requests/{id}/resolve`; live
  via SSE `builder.message`, `builder.attachment.updated`, `builder.request.*`, `builder.changeset.*`.

## Pane B — KB editor (Редактор)

The precise path. A structured view of the **same** draft, every row editable, every row showing its
**review state** and **provenance**.

- **Блоки** — four tiles: **Идентичность · Цель · Качество · Поддержка**. Click → an inline editor
  (textarea). Manual edits save directly (the human is reviewing as they type — `PUT …/blocks/{key}`).
  An agent-proposed block edit appears instead as a **diff card** in the chat (never a silent overwrite).
- **Темы** — the topic list; each row: slug, **media count**, a **review badge** (`proposed` amber /
  `approved` green / `rejected` grey). Expand a topic →
  - its **body_md** (editable; `{{price.*}}` tokens rendered as subtle chips, never raw digits);
  - its **media gallery** — one card per asset: thumbnail/kind icon, **its own description** (the
    selection cue), `asset_kind` (image/video/document/audio/**link**), and a **provenance** chip.
    Add media = attach an uploaded `media_id` **or** paste a **link** URL.
  - **proposed** rows carry **Принять / Отклонить**.
- **Цены** — a token→value table; a value changed by the agent shows a **⚠** until its `confirm_price`
  is resolved. Edit/add is direct in the editor (`PUT/POST …/prices`).
- **▸ Backed by:** `GET /assistant/config?state=draft`, `PUT …/blocks/{key}`, `…/topics`, `…/assets`,
  `…/prices`, `POST /assistant/review`; live via SSE `builder.draft.updated`.

## The git-like diff card (changesets) — the headline interaction

For **important** changes (config blocks, prices, deletes, merges, bulk intake — `11`, §5) the agent
proposes a **changeset** rendered as a familiar diff:

```
┌ Изменение: «Добавить тариф Рост и обновить цену»  ────────────────────────┐
│ из: сообщение #12 · 4 операции · нужно: подтвердить цену                   │
│                                                                            │
│  БЛОК quality                                                              │
│    - всегда отвечать в течение часа                                        │
│    + всегда отвечать в течение часа; при оплате — не торопить              │
│                                                                            │
│  ТЕМА tariffs                                          [создать]           │
│    + body: «4 тарифа … {{price.start}} / {{price.growth}} …»               │
│                                                                            │
│  ЦЕНА price.growth                                     ⚠ требует подтв.    │
│    - 25 000 ₸        + 28 000 ₸                                            │
│                                                                            │
│  АССЕТ tariffs_growth (image)                          [создать]           │
│    + описание: «Карточка Рост — когда клиент сфокусирован на Рост»          │
│                                                                            │
│            [ Применить всё ]   [ Отклонить ]        раскрыть пооперационно ▸ │
└────────────────────────────────────────────────────────────────────────────┘
```

- **Per-field red/green** like a git hunk; `create`/`delete` show only the added/removed side.
- **Atomic:** **Применить всё** runs the apply transaction (`11.1`) — all ops or none. **Отклонить**
  discards, changing nothing.
- **Blocked when incomplete:** if an op `needs` an unresolved request (e.g. the price's `confirm_price`),
  **Применить** is disabled with a hint — the operator resolves the popup first. This is the guardrail
  that stops an unconfirmed number from being applied.
- **Provenance** in the header ("из: сообщение #12") — one click to the chat turn that proposed it.
- **▸ Backed by:** `GET …/changesets/{id}`, `POST …/changesets/{id}/apply|discard`; live via SSE
  `builder.changeset.*`.

## Publish bar & flow

- **Готовность ▸** opens a small checklist (derived, not nagging): blocks filled? topics cover the top
  questions? every asset has a description? every `{{token}}` has a price? any open popup/diff?
- **Опубликовать** is enabled only when the deterministic gate can pass; clicking runs `POST
  /assistant/publish`. On refusal (`EVAL_GATE_FAILED`) it shows exactly what blocks publish (failing
  metric and/or the list of unresolved requests), each a link to the offending row/popup.
- On success: a toast **"Опубликовано v2"**, the brain reloads, the builder session closes, and a fresh
  draft can be forked for the next round. **Откатить** (rollback) lives in a version-history drawer
  (Tier 3, `GET /assistant/versions` + `POST /assistant/rollback`).
- **▸ Backed by:** `POST /assistant/publish`, `GET /assistant/versions`, `POST /assistant/rollback`;
  live via SSE `assistant.published`.

## Where it lives in the app shell & nav

`/assistant` is added to the left nav rail (`5-ui-pages.md`) **only when this build ships** (no dead
placeholders — the v1 rail has just Inbox). The **Playground** (dry-run against the draft) is a Tier-3
drawer reusing the same **1–3 option cards** as the Chatboard assistant panel (`5-ui-pages.md` §2), so
the operator can test the draft KB before publishing.

## Out of scope (this build)

Per `5-ui-pages.md` discipline: no analytics on the KB, no multi-draft branching (one draft per org),
no inline vision/transcription preview (auto-extraction is a later drop-in behind the same popups), no
i18n (Russian UI). Not shown, not stubbed.
