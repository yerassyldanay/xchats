# KB Builder — build plan, testing, risks

How to build the builder in safe, shippable slices. This is the **deferred CMS** — DoD **Phase 4B**
(`0.1-definition-of-done.md`), built *after* the v1 vertical slice (inbox + draft loop) proves the
wedge. It does not change the v1 bar. Follows the repo's phasing + **isolated, one-command, no-external-
network** test discipline (`2-architecture.md`, `6-isolated-testing.md`).

## The load-bearing insight: most of this needs no live LLM

The builder's *correctness* is **deterministic** and testable offline; only the agent's *judgment*
needs a model:

```text
deterministic (unit/integration, no LLM)        judgment (fixture transcripts + nightly live)
─────────────────────────────────────────       ──────────────────────────────────────────────
changeset apply transaction (atomic, idempotent) "ask vs. guess" decisions
diff computation (before/after per field)         topic placement / append-vs-new
route enforcement (price ⇒ changeset+request)     description quality
normalizer fallback (image ⇒ needs_description)   merge proposals
publish gate (price=1.0, asset≥0.9, no open reqs) improvement suggestions
seed import / fork / rollback
```

So CI runs a **fake LLM adapter** that returns *canned tool-call transcripts* (like the existing fake
Evolution returns canned webhooks) — the whole builder loop is exercised end-to-end with **no network**.
The model's judgment is graded separately by the **golden gate** + a manual/nightly live run.

## Phase 11A — Snapshot store + editor (the foundation)

**Goal:** realize the deferred `ai_*` snapshot tables and a read/CRUD editor over a draft — the floor
everything (and the *real* brain) stands on. No agent yet.

- **Backend:** migration `0003` (`11.1`); `internal/assistant/kb` — draft store (load/fork-from-published
  /CRUD/publish/rollback), seed import from `0002_seed.sql` on first boot; `internal/httpapi`:
  `/assistant/config`, `/assistant/blocks|topics|assets|prices`, `/assistant/publish` (gate +
  swap + brain reload), `/assistant/rollback`, `/assistant/versions`.
- **Frontend:** `views/Assistant.vue` (editor pane only), `stores/assistant.ts`.
- **DoD:** seed loads as published v1 on boot; `POST /assistant/builder/session` forks a draft;
  editor CRUD round-trips; **publish** runs the deterministic gate and atomically swaps live (brain
  answers from the new snapshot); **rollback** restores a prior version; `ai_snapshots_one_published`
  / `_one_draft` hold under concurrent writes.
- **Test:** unit (fork copies all rows; publish gate refuses a bad snapshot; rollback); integration
  (boot → seed → edit draft → publish → brain reload reads new values). No LLM.

## Phase 11B — Builder chat + agent (text · note · link)

**Goal:** configure-by-chat for the non-media inputs — the core experience.

- **Backend:** migration `0004` (builder + changeset tables); `internal/assistant/builder` —
  `agent.go` (bounded loop), `tools.go` (catalog + dispatch with route enforcement), `prompt.go`
  (system prompt + digest builder), `normalize.go` (text/URL/PDF + the always-on ask fallback);
  `internal/httpapi/builder.go` (session/messages/attachments); wire `ai_builder` queue task; SSE
  `builder.*` on the existing hub.
- **Frontend:** `components/BuilderChat.vue` + `RequestPopup.vue`; the two-pane `/assistant`.
- **DoD:** an operator message + a link/note yields **proposed** topic/block rows with provenance; an
  ambiguous input yields a **request** popup (not a row); resolving a popup **nudges** the agent;
  prices appear only as `{{tokens}}` + a `confirm_price`. Everything visible live over SSE.
- **Test:** **fake LLM** transcripts drive the loop → assert rows/requests; unit-test route enforcement
  (a `propose_price` always emits changeset+request; an undescribed asset always emits
  `describe_media`); normalizer fallback unit tests. Live judgment run is manual.

## Phase 11C — Changesets + git-like diffs

**Goal:** the headline "diff before important updates," dedup/merge, provenance surfacing.

- **Backend:** `internal/assistant/changeset` — diff compute (before/after per field) + the **apply
  transaction** (idempotent, `needs[]` gating); `open_changeset`/`request_review`/`merge_*`/`delete`
  tool routes; changeset endpoints (`11.2`).
- **Frontend:** `components/DiffCard.vue` (per-field red/green, Apply/Discard, blocked-when-incomplete).
- **DoD:** a config-block edit, a price change, a delete, a merge, and a **bulk** PDF intake each arrive
  as a **changeset**; **Apply** mutates the draft atomically and is idempotent (replay → `CONFLICT`); a
  changeset with an unresolved `needs` **cannot apply**; re-feeding a URL/topic raises `resolve_duplicate`,
  not a twin.
- **Test:** golden before/after fixtures for diff + apply; idempotency/replay; "apply blocked by open
  price request"; dedup raises a request. No LLM for any of these.

## Phase 11D — Media intake (operator-described)

**Goal:** files become described assets + (when knowledge-bearing) companion topics — *without* costly
auto-extraction.

- **Backend:** attachment upload (reuse blob) + `describe_media`/`choose_topic` flow; the
  media-as-knowledge companion-topic rule (`8-ai-assistant.md`); `asset_kind='link'` as a first-class
  asset; attachment `norm_state` machine + `builder.attachment.updated`.
- **Frontend:** attachment chips, the `describe_media` popup (thumbnail + textarea), the media gallery
  in the editor.
- **DoD:** an uploaded image becomes an `ai_assets` row **only after** a `describe_media` answer; a
  knowledge-bearing image also gets a companion topic; a link is added as an asset; nothing media-shaped
  is auto-captioned (the popup is the path). The `Normalizer` port is in place so vision/transcription
  can drop in later behind the same popup (pre-fill, no UX change).
- **Test:** "image ⇒ needs_description ⇒ asset only after resolve"; companion-topic creation; link asset.

## Phase 11E — Publish from the builder + polish

**Goal:** close the loop — review queue, coverage checklist, publish/rollback from the builder UI.

- **DoD:** the publish bar's checklist is derived; **Опубликовать** is gated and, on refusal, links to the
  exact blocker (failing metric or unresolved request); a clean draft publishes, the session closes, the
  brain reloads (`assistant.published`); rollback works from the version drawer.
- **Test:** publish refuses on (a) a failing metric, (b) any pending request, (c) an unresolved
  `{{token}}`; publish succeeds on a clean draft and the brain serves it. Mostly deterministic; one
  live smoke for an end-to-end "build a topic by chat → publish → brain answers from it".

## Isolated test harness (extends `6-isolated-testing.md`)

- **Fake LLM adapter** (`LLM_DRIVER=fake`) returning canned tool-call transcripts per input fixture —
  the builder analogue of fake Evolution. Drives 11B–11E with **no external network**, one command.
- **Fixtures:** a small set of `(operator input → expected tool calls → expected draft effects)` cases
  committed under `plan/captures/` or `backend/internal/assistant/builder/testdata/` — covering text, a
  link, a PDF→multi-topic, an undescribed image, a duplicate, and a price change.
- **`make test-e2e`** gains a builder leg: boot Postgres + backend + fake LLM, run a session that builds
  a topic, raises + resolves a `describe_media` and a `confirm_price`, applies a changeset, and
  publishes — asserting the draft rows, the apply atomicity, the gate, and the brain reload.
- **Live (manual, outside isolation):** point `LLM_BASE_URL` at a real model and run one real authoring
  session to grade judgment quality + the golden gate (the honest "is the builder any good?" check).

## Risks & mitigations

| Risk | Mitigation |
|---|---|
| Agent writes wrong/garbage rows | Four gates (`11`, §8); proposed-only; route enforcement in code, not model discretion; everything reversible (discard/reject/rollback) |
| A wrong **price** ships | Token discipline + `confirm_price` + changeset `needs[]` block + publish gate price-safety = **1.0** (hard) |
| URL/PDF extraction is noisy | Auto-extract is a *proposal* behind review; ask-fallback always available; provenance one-click to source |
| LLM cost / runaway loops | Digest (not full KB) in context; bounded tool calls/run; cached prefix; on-demand (operator-driven), not background crawling |
| Brain coupling / regressions | Only one additive brain touch (`support_policy` into `[C]`); builder writes the *draft*, never the live snapshot or the hot path |
| Cross-border PII (compliance) | Builder ships **operator-authored business content**, not customer PII — lighter than the brain's boundary; still honors `LLM_BASE_URL` (`2-architecture.md`) |
| Scope creep into auto-vision | Explicitly phased out (11D ships operator-described media); `Normalizer` port is the seam so it drops in later with no UX/schema change |

## Sequencing recommendation

Build **11A first** — it is independently valuable (it's also the prerequisite for the *real* ported
brain to read an editable snapshot instead of the Build-0 stub) and it de-risks everything after it. Then
11B (the core chat), 11C (the diffs), 11D (media), 11E (publish polish). Each phase is shippable and
testable in isolation; none is required by the v1 vertical slice, so this build can start whenever the
inbox + draft loop are stable.
