# Endpoints — Request & Response Parameters

Full request/response detail for every endpoint. Conventions, the `{payload, errcode, message}`
envelope, error codes, and HTTP statuses are in `7-api-contracts.md`. Below, **Response** shows
the contents of `payload` on success (the envelope wraps it).

## Auth & users

### POST /xchats/api/v1/auth/login
- **Body:** `{ "email": "a@b.com", "password": "…" }`
- **Response:** `{ "user": { "id","email","name" }, "organization": { "id","name" } }` (sets session cookie)
- **Errors:** `VALIDATION_ERROR` (400), `UNAUTHORIZED` (401 bad creds)

### POST /xchats/api/v1/auth/logout
- **Body:** none → **Response:** `null`

### GET /xchats/api/v1/me
- **Response:** `{ "user": {…}, "organization": {…} }` · **Errors:** `UNAUTHORIZED`

### GET /xchats/api/v1/users  (list users)
- **Query:** `page`, `page_size`
- **Response:** `{ "items": [{ "id","email","name","created_at" }], "page","page_size","total" }`

### POST /xchats/api/v1/users  (create user)
- **Body:** `{ "email","password","name?" }`
- **Response:** `{ "id","email","name" }` (201) · **Errors:** `CONFLICT` (email exists), `VALIDATION_ERROR`

## Organization

### GET /xchats/api/v1/organization
- **Response:** `{ "id","name","auto_response_mode","auto_response_window" }`

### PATCH /xchats/api/v1/organization
- **Body (any subset):** `{ "name?", "auto_response_mode?": "NEVER|CONFIGURE_TIME|ALWAYS", "auto_response_window?": { "start":"09:00","end":"18:00" }  (UTC times-of-day) }`
- **Response:** the updated organization · **Errors:** `VALIDATION_ERROR`

## WhatsApp accounts (manager)

### GET /xchats/api/v1/whatsapp-accounts
- **Response:** `{ "items": [ WhatsAppAccount ] }` — **all** Evolution instances, each with `assigned` + status.

### POST /xchats/api/v1/whatsapp-accounts  (add)
- **Body:** `{ "display_name","instance_name" }`
- **Response:** `WhatsAppAccount` (201, `connection_status: qr_required`) · **Errors:** `CONFLICT` (name taken)

### GET /xchats/api/v1/whatsapp-accounts/{id}
- **Response:** `WhatsAppAccount`

### POST /xchats/api/v1/whatsapp-accounts/{id}/qr  ·  GET …/qr
- **Body:** none.
- **Response:** `{ "status": "qr_required|connected", "qr_code": "2@…|null", "pairing_code": "WZYE…|null", "expires_at": "ts" }`
- GET is the poll variant (every 2–3s while `qr_required`).

### POST /xchats/api/v1/whatsapp-accounts/{id}/assign  ·  …/unassign
- **Body:** none → **Response:** updated `WhatsAppAccount` (`assigned: true|false`)
- **Errors:** `INSTANCE_NOT_FOUND`

## Inbox

### GET /xchats/api/v1/chats
- **Query:** `status?`, `assignee?` (`me|unassigned|uuid`), `wa_account_id?`, `q?`, `page`, `page_size`
- **Response:** `{ "items": [ Chat ], "page","page_size","total" }`

### GET /xchats/api/v1/chats/{id}/messages
- **Query:** `before?` (cursor ts/id), `limit?`
- **Response:** `{ "items": [ Message ], "next_before": "cursor|null" }`

### POST /xchats/api/v1/chats/{id}/messages  (send)
- **Body:** `{ "text?": "hello", "media_ids?": ["uuid", …] }` — optional `text` and an optional list of
  previously-uploaded `media_ids` (from `POST …/media`).
- **Fan-out (Evolution sends one file per call):** the request produces **one outbound message per part** —
  the `text` is one message and **each `media_id` is its own message** (each its own `wa_messages` row /
  `Message`). So a body with `text` + 2 media yields **3** messages.
- **Response:** `{ "items": [ Message ] }` — the created messages in send order (each `status` starts
  `queued`). · **Errors:** `ACCOUNT_NOT_CONNECTED` (409), `SEND_FAILED` (502), `RATE_LIMITED` (429)

### POST /xchats/api/v1/chats/{id}/media  ·  POST /xchats/api/v1/media  (upload)
- **Body:** `multipart/form-data` with a `file` part → stored to the blob.
- **Response:** `{ "media_id": "uuid", "media_type": "image|video|audio|document", "mimetype": "…",
  "file_name": "…", "file_size": 0, "url": "/xchats/api/v1/media/{id}" }` — the `media_id` is then used in a
  send body above. · **Errors:** `VALIDATION_ERROR` (400), `MEDIA_UNAVAILABLE` (502)

### POST /xchats/api/v1/chats/{id}/assign
- **Body:** `{ "user_id": "uuid|null" }` (null = unassign) → **Response:** updated `Chat`

### POST /xchats/api/v1/chats/{id}/read
- **Body:** none → **Response:** `{ "unread_count": 0 }`

### GET /xchats/api/v1/contacts  ·  GET /xchats/api/v1/contacts/{id}
- list **Query:** `q?`, `page`, `page_size` → `{ "items":[ Contact ], … }`; detail → `Contact` (+ recent chats)

### GET /xchats/api/v1/media/{id}
- **Response:** the **binary media stream** (not the envelope); `Content-Type` per the asset. `404` if unknown, `502 MEDIA_UNAVAILABLE` if not downloadable.

## AI assistant

> **v1 builds the draft endpoints** (Suggest / list / approve, below) **and the Knowledge-Base
> (Playground) CMS** (`/playground/*`, next) that powers the **Конструктор** (`/playground`) and
> **Редактор** (`/knowledge-base`) pages (see `5-ui-pages.md` §6/§6b). The earlier
> `/assistant/config|publish|playground` design is **superseded** by `/playground/*` below.

### AI Knowledge Base — `/playground/*`  (KB builder + editor; one live KB)

> All require a session. **Writes return the refreshed `DraftView`** and broadcast `kb.row.changed`.
> Writes accept an **optional `If-Match`** header = the draft `config.updated_at` (RFC3339Nano) →
> `409 DRAFT_STALE` if the draft moved since load (omit ⇒ last-write-wins). Versioning exists
> server-side but is **hidden in the UI** — `/playground/rollback` exists yet is intentionally unused.

- **GET /playground/draft** — read-only. **Response:** `DraftView`, or `{ "has_draft": false }` (never opens/clones).
- **POST /playground/draft** — open a draft (clones the live KB as `approved` rows if none). **Response:** `201 DraftView`.
- **DELETE /playground/draft** — discard the working copy. **Response:** `null`.
- **POST /playground/draft/topics** — upsert a topic. **Body:** `{ "slug"(req), "lang?", "title?", "keywords?", "body_md?" }`. **Errors:** `VALIDATION_ERROR` (slug required).
- **DELETE /playground/draft/topics/{slug}** → `DraftView`.
- **POST /playground/draft/assets** — upload an asset (**multipart**). **Form:** `file`(req), `topic_slug?`, `description?`, `lang?`. Stores bytes → `url:/xchats/api/v1/media/{ref}`.
- **PATCH /playground/draft/assets/{ref}** — **Body:** `{ "description?", "topic_slug?" }`.
- **DELETE /playground/draft/assets/{ref}** → `DraftView`.
- **POST /playground/draft/values** — upsert a value. **Body:** `{ "token"(req), "lang?", "value_text?", "description?" }`. **Errors:** `VALIDATION_ERROR` (token required).
- **DELETE /playground/draft/values/{token}?lang=** → `DraftView`.
- **PATCH /playground/draft/config** — **Body:** any of `{ "persona?", "mission?", "guardrails?", "language_policy?", "reply_max_words?" }` (omitted = unchanged).
- **POST /playground/draft/review/{kind}/{id}** — approve/reject a row. `kind` ∈ `topics|assets|values`, `id` = row uuid. **Body:** `{ "state": "approved|rejected" }`. **Errors:** `VALIDATION_ERROR` (bad kind/state).
- **POST /playground/draft/materials** — stage one input. **Either** multipart `file`, **or** JSON `{ "source_type":"text|url", "text?", "url?" }`. Text is born `ready`; file/url enqueue extraction. **Response:** `201 KbMaterial`; broadcasts `kb.material.updated`.
- **GET /playground/draft/materials** — **Response:** `{ "items": [ KbMaterial ] }` (`{ "items": [] }` if no draft).
- **POST /playground/chat** — run one builder turn. **v1 = deterministic `RuleSynthesizer`** (concatenates `ready` materials into a topic + regex-detects ₸ values; the instruction seeds slug/title/keywords — *not* a conversational LLM in v1). **Body:** `{ "instruction?": "…" }`. **Response:** `{ "result": { /* synthesis summary */ }, "draft": DraftView }`. **Errors:** `INTERNAL` (503, builder unavailable).
- **GET /playground/requests** — open popups. **Response:** `{ "items": [ KbRequest ] }`.
- **POST /playground/requests/{id}/resolve** — answer a popup, mutate the draft, mark resolved. **Body:** `{ "state?": "resolved|dismissed", "resolution": { … } }`.
  - `confirm_value` → `resolution { "value_text":"…" }` (empty ⇒ accept `context.suggested`); upserts the value `approved`.
  - `describe_media` → `resolution { "description":"…" }`; fills the asset description (or the material's extracted text).
  - `dismissed` mutates nothing. **Errors:** `NOT_FOUND` (no such request), `VALIDATION_ERROR`.
- **POST /playground/publish** — **"Сохранить в базу".** Runs the deterministic gate over **`approved`** rows; on pass, atomically promotes the draft to the live KB (non-approved rows dropped) and **hot-reloads the brain**. **Response:** `{ "version": n }`; broadcasts `kb.published`. **Errors:** `VALIDATION_ERROR` **422** — gate failed (`message` = `"publish gate failed: <reasons>"`, a human-readable string, **not** a structured list); `VALIDATION_ERROR` 400 — no open draft. *"Готовность к публикации" is derived client-side from `review_state` counts + open `requests`.*

### POST /xchats/api/v1/chats/{id}/ai-drafts  (Suggest — v1 on-demand trigger)
- **Trigger** the brain for the chat's latest inbound (the "Generate suggestions" button). Inserts a
  `state='generating'` row (the lock) and broadcasts `ai_draft.generating`, then enqueues an `ai_draft`
  task → `HandleMessage` fills the **one `ai_suggestions` row** (1–3 options in `jsonb`), flips it to
  `suggested`, and broadcasts `ai_draft.created`.
- **Response:** `202 { "trigger_message_id": … }` (the options arrive over SSE). **Single in-flight per
  chat:** if a `generating` or `suggested` row already exists it is returned instead of starting a
  second; a concurrent click loses the unique race with `409`.
- **Errors:** `AI_UNAVAILABLE` (503, LLM down — no options, the user replies normally), `CONFLICT`
  (409, a pending suggestion already exists).

### GET /xchats/api/v1/chats/{id}/ai-drafts
- **Response:** `{ "items": [ AiDraft ] }` — the **1–3 pending options** for the chat (or one option
  with `escalate=true` when the brain has no answer).

### POST /xchats/api/v1/ai-drafts/{id}/approve  (send this option — `{id}` = the `ai_suggestions` row)
- **Body:** `{ "chosen_ordinal": 1, "edited_text?": "…", "media_ids?": ["uuid", …] }` — pick which of the
  1–3 options to send; the user may tweak the text and detach media before sending (final text + the
  kept media list; omitted media is detached). Attaching a *new* file needs the asset catalog (deferred
  — see the AI Knowledge Base `/playground/draft/assets`).
- **Response:** the resulting `Message` (sent via the outbound pipeline, `sender_type: ai`); the
  suggestion is stamped `chosen_ordinal` + `sent_message_id` + `state='resolved'`.
- **Idempotent / single-send:** conditional `UPDATE … WHERE state='suggested'`. Already approved
  → `409 CONFLICT`; a newer inbound arrived since → `409 DRAFT_STALE` (the suggestion is `superseded`).
  On success an `ai_draft.updated` event clears the cards on every screen.
- **Errors:** `CONFLICT` (409, already approved), `DRAFT_STALE` (409, superseded by a newer inbound),
  `ACCOUNT_NOT_CONNECTED`, `SEND_FAILED`.

## Realtime

### GET /xchats/api/v1/realtime  (SSE)
- **Stream events** (`event:` + JSON `data:`):
  `message.created`, `message.updated`, `chat.created`, `chat.updated`,
  `assignment.changed`, `ai_draft.generating`, `ai_draft.created`, `ai_draft.updated`,
  `wa_account.status_changed`,
  `kb.material.updated` (`{material_id,status}`), `kb.row.changed` (`{version}`), `kb.published` (`{version}`).
- Each `data` carries the relevant entity (Message / Chat / AiSuggestion / WhatsAppAccount); the
  `kb.*` events carry only the small payloads noted above — the client refetches the `DraftView`.
- **Broadcast scope:** events are **org-scoped and fanned out to every connected client** for that org —
  not only the user who triggered the action. So all agents viewing a chat receive the same
  `message.created` and `ai_draft.*` events; `ai_draft.generating` is what disables the Generate button
  for everyone while one suggestion is in flight.

## Evolution webhook ingress

### POST /evolution/api/v1/webhook/{wa_account_id}  (+ /{event} if webhookByEvents)
- **Auth:** shared token from `.env`, **header only** (no query param, so it never lands in logs) →
  `WEBHOOK_UNAUTHORIZED` (401) if wrong. Reject fast at the edge if `{wa_account_id}` is
  unknown/unassigned, or if the payload `instance`/`instanceId` ≠ the path account (log + ignore).
- **Body:** the raw Evolution event (e.g. `messages.upsert`, `messages.update`, `send.message`,
  `connection.update`, `qrcode.updated`, `contacts.*`, `chats.*`) — shapes in `captures/`.
- **Behavior:** enqueue the raw event to the in-memory queue → return 200 fast (no DB write).
- **Response:** `{ "payload": null, "errcode": "OK" }` (Evolution only needs a 2xx).
