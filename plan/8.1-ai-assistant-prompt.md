# AI Assistant — Prompt & Conversation Flow

How the brain builds its prompt and drives a conversation. Implementation:
`examples/repos/xpayment-crm/internal/usecase/assistant/prompt.go`.

## The prompt has two parts

### 1. System prefix `[A]–[E]` — cache-stable, rebuilt only on publish (`BuildSystem(snapshot)`)

- **[A] Frame** — hard, code-owned rules (never editable): you are a drafting engine that writes
  ONE reply for a human to review; **answer only from the KB** (else escalate); **prices/limits are
  tokens, not digits**; **attach media only by catalog refs, max 3**; **reply in the customer's
  language (KZ+RU mix → Russian)**; **~120 words**, warm, one next step; never handle passwords;
  `profile_patch` only newly-confident facts; **must call `emit_draft`**.
- **[B] Identity** — `persona` (+ `mission`) from config.
- **[C] Guardrails** — `guardrails` (+ `language_policy`) from config.
- **[D] Knowledge base** — each topic rendered as `# topic: <slug> (<language>)` + keywords + body.
- **[E] Media catalog** — rows `ref | kind | topic | description`.

### 2. User block — per message (`BuildUser(profile, window, current)`)

`PROFILE` (JSON of known facts) → `CONVERSATION` (the recent window, **oldest first**, as
`role: content`) → `CURRENT MESSAGE`.

## Language — how it knows what to answer in

Three layers: the **[A] rule** ("reply in the customer's language; KZ+RU → Russian"), the config
**language policy** ([C]), and each topic's `language` tag ([D]). The model also returns
`reply_language` for observability.

## Conversation flow — start / middle / end

There is **no hardcoded state machine**. The flow is driven by the **persona/guardrails** plus the
model's `suggested_status.stage`, with the message window giving continuity. The shape we encode in
the persona:

- **Start (greeting)** — brief warm intro; ask what the customer needs / which product or question.
- **Middle (qualify → present)** — ask the missing qualifying fact (one at a time), answer from the
  KB, attach the right media, inject prices; record new facts to the profile.
- **End (closing)** — confirm the next step / thank them / "write any time"; optionally propose a
  follow-up via `suggested_callback`.

Each turn the model picks the `stage` (e.g. `greeting → qualifying → presenting → closing`); it is
stored on the conversation (via the profile's `stage`) so the next turn knows where things stand.

## What to ask vs. suggest vs. escalate

- **Ask** when a qualifying fact is missing — one concise question.
- **Suggest/answer** when the KB covers it — concrete answer (+ optional media, + price tokens).
- **Escalate** when the KB does not cover it — `escalate: true` + a short holding reply; never guess.
