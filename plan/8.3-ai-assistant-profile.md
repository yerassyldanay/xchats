# AI Assistant — Contact Profile

How the brain builds and uses a per-contact profile. Implementation: `profile_patch` in
`examples/repos/xpayment-crm/internal/domain/draft.go` and the profile step in
`internal/usecase/assistant/brain.go`.

## What it is

A small JSON of **known facts** about the contact plus a conversation `stage`. Example keys:
`business_type`, `monthly_volume`, `interested_tariff`, `current_payment_method`,
`preferred_language`. Stored on the contact (in xchats: Postgres); injected into the prompt's
`PROFILE` block every turn.

## How it's built

Each turn the model returns `profile_patch` containing **only facts it is newly confident about**
(the system prompt forbids inventing fields). Post-processing **merges** the patch onto the contact
(read-modify-write — never blind-clobber existing values).

The special **`stage`** key is **stripped** from the profile and stored as the conversation status
(e.g. `greeting / qualifying / presenting / closing`) — it describes where the conversation is, not
a fact about the contact.

## How it's used

- Fed back as `PROFILE` context so the assistant doesn't re-ask known facts and tailors answers.
- Drives what's still missing → the next question to ask.
- Populates the contact panel in the UI.

## Notes

- Attribute keys are **pre-defined** (so the UI/columns stay stable); unknown keys are ignored.
- Profiles are per-contact and accumulate across the conversation, complementing the
  recent-message window (see 8.1) — the window is short-term memory, the profile is durable memory.
