# AI Assistant — LLM Providers

The brain is **provider-neutral**: it speaks the OpenAI-compatible `chat/completions` API with a
**forced `emit_draft` tool**, so the same code works across providers. Implementation:
`examples/repos/xpayment-crm/internal/infrastructure/llm/openrouter.go`.

## Supported providers

`openrouter | openai | gemini` — and anything else that is OpenAI-compatible. They all accept the
same request shape; only the base URL, API key, and model names differ.

## Config (env — `LLM_*` only)

- `LLM_PROVIDER` — `openrouter | openai | gemini` (selects the default base URL).
- `LLM_API_KEY` — the provider key.
- `LLM_BASE_URL` — optional override (self-host / proxy / a provider not in the list).
- `LLM_FAST_MODEL` — a cheap/quick model; `LLM_THINKING_MODEL` — a stronger one.
- `LLM_MAX_TOKENS`, `LLM_TEMPERATURE`.

Per the config split (see `2-architecture.md`): the **key** lives in `.env`; model names and limits
can live in `config.yaml`.

## How it's called

`POST {base}/chat/completions` with the `[A]–[E]` system prefix + the per-message user block and a
**forced tool call** (`emit_draft`) so the output is strict JSON. The response is **defensively
parsed**; if a provider doesn't support tool calls, it falls back to parsing JSON from the message
content. **Switching providers is a config change — no code change.**
