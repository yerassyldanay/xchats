# AI Assistant — Port Checklist

How to port the working brain from the submodule (`examples/repos/xpayment-crm/`) into the xchats
backend. The brain logic is reused **as-is**; only the edges change (Chatwoot → xchats Postgres,
SQLite → Postgres, draft → `xchats.ai_drafts`). Reference: `examples/repos/xpayment-crm/IMPLEMENTATION.md`.

## What changes vs. what stays

The brain's core is decoupled by ports: `assistant.HandleMessage(ctx, ChatID, inbound) -> Draft`
reads via a conversation/profile reader, drafts via an LLM `Drafter`, and **writes nothing** — the
caller persists. So the port is small: swap the reader + the persistence side, keep everything else.

## Reuse as-is (copy; only rewrite the Go module path)

Rewrite import path `github.com/yessaliyev/xpayment-crm` → the xchats backend module during copy.

| From (submodule) | To (xchats backend) | Notes |
|---|---|---|
| `internal/domain/{catalog,draft,message,content,validate}.go` | `internal/assistant/domain/` | `RawDraft`, `Draft`, `Snapshot`, `PriceBook.Render`, `ResolveAssets` — pure, unchanged |

| `internal/usecase/admin/*`, `internal/ports/http/admin/*` (+ templates, minus `whatsapp.html`) | `internal/assistant/adminui/` | persona/KB/price CRUD, draft→publish→rollback, Playground |

## Adapt

| Item | Action |
|---|---|
| The conversation/profile reader port (in the submodule, `ChatwootReader` with `Window` + `Profile`) | Implement a **new xchats Postgres reader** with the same interface: `Window` = last ~15 `xchats.messages` rows for the thread (mapped to `domain.Message{Role: customer if direction='in' else agent, Content, ...}`); `Profile` = `xchats.contacts.attributes` (+ thread `stage`/`history_state` → so the brain sees `context_state`). |
| Draft persistence (submodule writes a Chatwoot private note) | The caller (a `process_event` → `ai_draft` worker job) takes the returned `Draft` and **inserts an `xchats.ai_drafts` row** + emits the realtime `ai_draft.created`. Escalation / `PricingError` / low confidence map to draft flags — **not** a note. |
| Config/snapshot store (`internal/infrastructure/sqlite/*`) | Reimplement on **Postgres** using `xchats.ai_snapshots` / `xchats.ai_topics` / `xchats.ai_assets` / `xchats.ai_prices` / `xchats.ai_audit_log` (see `9-database-schema.md`). Keep the publish/rollback/dedup semantics. |
| Config catalog (`internal/infrastructure/config`) | Keep `LLM_*`, `Admin`, media settings; drop the Chatwoot/Evolution-provisioning blocks. Fold into the xchats `internal/config` (`.env` + `config.yaml`). |
| `asset_url` resolution | Asset refs resolve to xchats' **media store** URLs (`xchats.ai_assets.asset_url` / blob store), not Chatwoot attachments. |

## Drop (Chatwoot-specific / replaced)

- `internal/infrastructure/chatwoot/*` — the Chatwoot REST adapter.
- `internal/usecase/whatsapp/*`, `internal/ports/http/admin/.../whatsapp.html` — Chatwoot-flavored Evolution provisioning (xchats has its own accounts/QR manager).
- `internal/ports/http/webhook.go` — Chatwoot webhook handler (xchats has its own `internal/webhook`).
- The old `internal/infrastructure/evolution/client.go` (v2.2.3-era) — xchats uses its own client (port of `scripts/evolution_client.py`).

## Wiring in xchats

- **Trigger:** the `process_event` worker, on a normalized inbound message, enqueues an `ai_draft`
  job → calls `HandleMessage(window, profile, snapshot)` → writes `xchats.ai_drafts` → `ai_draft.created`.
- **Auto-send gate:** honor `xchats.organizations.respond_mode` (`NEVER|CONFIGURE_TIME|ALWAYS`). Default suggest-
  only; auto-send (Phase 3) reuses the outbound send pipeline with `sender_kind='ai'`.
- **Don't draft on incomplete context:** while `history_state` is `syncing/partial`, mark the draft
  `context_state` accordingly (the brain already accepts this signal).

## Port gate (done when)

- `go test ./internal/assistant/...` passes after the module-path rewrite (the submodule's
  `brain_test`/domain tests are the parity check).
- A `Playground` call returns a `Draft` from a Postgres-loaded snapshot.
- An inbound fixture (`captures/`) produces an `xchats.ai_drafts` row + an `ai_draft.created` event end-to-end.
